# ERP 照片与容量维护

## 本次改动
- 云端商品按 product_no 游标分批读取，完整读取后才交给库存页面。
- 读取错误、重复编号或读取数量异常会报错，不用空数组覆盖本地商品。
- 同时发起的云端读取共用一个请求；下一次读取仍取最新数据。
- 新上传照片在原有处理流程之后生成最长边 360 像素的独立 JPEG 缩略图。
- 数据库、备份和点击预览继续使用主图地址，不把缩略图写成主图。
- 历史照片地址不改写，不自动迁移或删除照片。
- 缩略图生成或上传失败则使用主图；显示缩略图失败则回退主图。
- 主图上传失败不保存残缺商品；表单及未上传照片保留，可直接重试。
- 照片缓存批量读取共用一个 IndexedDB 连接，而非每件商品打开一次。

## 原图和备份
此处的主图指现有上传流程处理后的图片。现有流程可能将大图缩至 1200 像素并压缩；本次没有进一步改变主图压缩设置。保留相机原始文件仍需另行归档。

JSON 备份中，云端照片保存的是网址，不是云端图片文件的独立副本。请勿把 JSON 当作对象存储备份；云端原文件被删除后，仅恢复 JSON 不能找回照片。缩略图可以重建，主图应独立备份。

## 大规模使用的边界
验证数据为一万件商品、三万个照片地址，不是向真实生产存储上传三万张照片。实际容量、流量额度、成本和网络速度仍取决于 Supabase 项目配置；本次没有修改套餐或付费设置。

每张新照片通常新增主图和缩略图两个对象。旧照片仍使用主图，未自动补生成历史缩略图。商品文字缓存仍使用现有浏览器存储机制，达到本地容量上限会提示；不能仅凭列表测试保证所有设备都能离线保存一万件完整商品。

继续扩容前，应核实存储额度、真实平均照片大小、独立图片备份，并使用真实数据检查全量同步和浏览器文字缓存容量。
